# CAN/LIN Bus Message Format Converter — Design Spec

**Date**: 2026-05-13
**Status**: Approved

## Overview

A desktop GUI tool that converts CAN/LIN bus log files between BLF, MF4, ASC formats,
and exports any of them to CSV. CSV is output-only (no reverse import).

Packaged as a single .exe that runs on clean Windows with no Python installation.

## Conversion Matrix

| From \ To | BLF | MF4 | ASC | CSV |
|-----------|-----|-----|-----|-----|
| BLF       | —   | ✓   | ✓   | ✓   |
| MF4       | ✓   | —   | ✓   | ✓   |
| ASC       | ✓   | ✓   | —   | ✓   |
| CSV       | ✗   | ✗   | ✗   | —   |

**9 valid paths**. Same-format is blocked by the UI (dropdown filters out input's extension).

## UI Design

- **Framework**: PySide6
- **Layout**: Vertical stack, single window (~420×380 px)
- **Theme**: Dark (Discord-inspired palette), applied via QSS stylesheet
- **Window title**: "CAN 报文格式转换工具"

### Widget order (top to bottom)

1. **Title bar** — app name, dark header
2. **Input file row** — read-only text field + "Browse" button (file filter: *.blf *.mf4 *.asc)
3. **Output format dropdown** — .blf / .mf4 / .asc / .csv (auto-excludes input extension)
4. **Output directory row** — read-only text field + "Browse" button
5. **Action buttons** — "单文件转换" (blue) + "批量转换" (green), side by side
6. **Progress bar** — indeterminate during conversion, resets on completion
7. **Status label** — shows current state / last result

### Behavior

- **Single file**: one input → one output in selected directory
- **Batch**: QFileDialog.getOpenFileNames for multi-select; each file converted individually, same format and directory applied to all
- Output filename = input filename with new extension (e.g., `log.blf` → `log.mf4`)
- If output file exists, append `_1`, `_2`, etc.
- Progress bar pulsed during conversion; runs in QThread to keep UI responsive

## Data Model (Internal Canonical Format)

All readers parse into a common `List[FrameRecord]`:

```
FrameRecord:
  timestamp: float       # seconds
  channel: int           # CAN channel
  arbitration_id: int    # CAN ID or LIN PID
  is_extended: bool      # True = 29-bit, False = 11-bit
  is_lin: bool           # True = LIN frame, False = CAN
  dlc: int               # data length 0–8 (CAN) or 0–8 (LIN)
  data: bytes            # raw payload
  bus: str               # optional bus name
```

Writers consume `List[FrameRecord]` and produce the target format.

## Tech Stack

| Layer | Library | Role |
|-------|---------|------|
| BLF read/write | `python-can` | BLFReader, BLFWriter |
| ASC read/write | `python-can` | ASCReader, ASCWriter |
| MF4 read/write | `asammdf` | MDF class |
| CSV write | `pandas` | DataFrame.to_csv |
| GUI | `PySide6` | Widgets, QThread, QSS |
| Packaging | `PyInstaller` | Single .exe, --onefile --windowed |

## Architecture

```
main.py              # Entry point, QApplication, main window
ui/
  main_window.py     # MainWindow class, layout, signal wiring
  theme.qss          # Dark theme stylesheet
converters/
  base.py            # Abstract Converter ABC + FrameRecord dataclass
  blf_converter.py   # BLF ↔ internal
  mf4_converter.py   # MF4 ↔ internal
  asc_converter.py   # ASC ↔ internal
  csv_writer.py      # internal → CSV (write-only)
  registry.py        # Dispatch table: ext → converter, format validation
worker.py            # QThread worker for async conversion
```

### Conversion flow

```
Input file → Reader → List[FrameRecord] → Writer → Output file
```

All converters go through the internal `List[FrameRecord]` representation.
No direct format-to-format coupling. Adding a new format = adding one reader/writer pair.

## Error Handling

- Unknown file extension → status message, no crash
- Corrupt/empty file → caught, logged to status label, skip in batch mode
- MF4 with unsupported channel structure → best-effort extract CAN/LIN signals
- Disk full / permission denied → caught at write time, shown in status

## Testing Strategy

Test-first approach using pytest:

1. **Unit tests**: each converter round-trips correctly (create FrameRecords → write → read back → compare)
2. **Integration tests**: real sample files (.blf/.mf4/.asc) → convert to each target → verify output can be read
3. **Edge cases**: empty file, single frame, max DLC, extended IDs, LIN frames, special characters in path
4. **UI tests**: smoke test that the window launches and buttons are wired (manual, not automated)

Sample test files stored in `tests/fixtures/` generated by python-can itself for BLF/ASC and asammdf for MF4.

## Packaging

```bash
pyinstaller --onefile --windowed --name "CAN-Converter" main.py
```

- `--onefile`: single .exe
- `--windowed`: no console window on launch
- Hidden imports added for python-can, asammdf, pandas
